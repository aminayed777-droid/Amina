ОБЪЯСНЕНИЕ ПРОЕКТА «ПЛАН НА ДЕНЬ»

1. ЧТО ЭТО ЗА САЙТ
Менеджер задач: можно выбрать исполнителя, добавить задачу, изменить её,
отметить выполнение или удалить. Задачи сохраняются после перезагрузки.

2. ЗА КАКУЮ ЧАСТЬ ОТВЕЧАЕТ КАЖДАЯ УЧАСТНИЦА
Дауренкызы Акбота — оформление: HTML, CSS, цвета, карточки, фотографии
и расположение элементов на компьютере и телефоне.
Даулетбек Энхара — функциональность: JavaScript, API, профили,
поиск, фильтры, действия с задачами и сохранение.

3. ЧЕМ ОТЛИЧАЮТСЯ ДВА ФАЙЛА
commits/01-akbota/index.html — промежуточный макет: дизайн, фотографии
и четыре примера задач. Кнопки отключены; API и сохранения ещё нет.
commits/02-enkhara/index.html — готовая версия: все функции подключены.
Для коммитов сначала ставим первый файл вместо корневого index.html,
делаем коммит, затем заменяем его вторым и делаем следующий коммит.
Подробные команды находятся в COMMITS.md.

4. ОСНОВНЫЕ ПОНЯТИЯ ПРОСТЫМИ СЛОВАМИ
HTML — задаёт структуру страницы: заголовки, карточки, формы и кнопки.
CSS — отвечает за цвета, размеры, шрифты, тени и адаптацию к экрану.
JavaScript — обрабатывает нажатия, получает данные и обновляет страницу.
API — способ получить задачи и пользователей с сервиса DummyJSON.
userId — номер исполнителя в задаче; он соответствует id его профиля.
Модальное окно — всплывающая форма добавления задачи или окно профиля.
localStorage — хранилище браузера для задач и изменений.

5. ЧТО ДЕЛАЮТ ФУНКЦИИ В ГОТОВОМ ФАЙЛЕ
sendRequest() — отправляет запрос к API и обрабатывает ошибки ответа.
loadTodos() — загружает задачи; при выборе сортировки запрашивает порядок у API.
loadUsers() — загружает пользователей: имена, username, аватары и сведения.
renderTeam() — показывает карточки Акботы и Энхары с фотографиями.
renderTask() — создаёт карточку одной задачи с исполнителем и кнопками.
renderTasks() — выводит список задач и обновляет счётчики.
getVisibleTodos() — отбирает задачи по названию, статусу и исполнителю.
openTaskDialog() — открывает форму создания или редактирования задачи.
openProfile() — открывает окно выбранного пользователя.
renderProfile() — показывает сведения пользователя и назначенные ему задачи.
saveChanges() — применяет изменения существующей задачи.
persistState() — записывает задачи, правки и удаления в браузер.
restorePersistedState() — восстанавливает сохранённые данные при открытии сайта.

6. ДЕЙСТВИЯ: АНГЛИЙСКИЕ НАЗВАНИЯ, ЗАПРОСЫ И КОД
Этот пункт относится к готовой версии сайта.
CRUD — четыре операции: Create (создать), Read (прочитать),
Update (изменить), Delete (удалить).

6.1. Получить данные — Read / Get, метод GET
GET /todos?limit=0 — получить все задачи, функция loadTodos().
GET /users?limit=0&select=... — получить пользователей, функция loadUsers().
limit=0 означает загрузку всего списка, select — выбор нужных полей.

6.2. Добавить задачу — Add / Create, метод POST
Кнопка сначала вызывает openTaskDialog() и открывает форму.
После заполнения и отправки формы выполняется POST /todos/add,
если выбран исполнитель из API. Передаются поля todo, completed и userId.
todo — название; completed — статус; userId — ID исполнителя.
Для Акботы и Энхары новая задача создаётся локально, без POST.
Все новые задачи получают локальный ID. После создания их изменение,
переключение статуса и удаление выполняются локально.

6.3. Изменить задачу — Edit / Update, метод PATCH
Действие в кнопке: data-action="edit".
openTaskDialog(todo) открывает форму с данными выбранной задачи.
При сохранении исходной задачи API выполняется PATCH /todos/{id}.
{id} заменяется номером задачи, например /todos/1.
saveChanges() применяет изменения к состоянию приложения.
Новая локальная задача редактируется без запроса к API.
Если исходную задачу API назначить Акботе или Энхаре, PATCH отправляется
без их локального userId; назначение сохраняется в браузере.

6.4. Выполнить или вернуть в работу — Toggle / Complete, метод PATCH
Действие в кнопке: data-action="toggle".
Для исходной задачи API: PATCH /todos/{id} с полем completed.
completed: true — выполнена; completed: false — не выполнена.
Для локальной задачи статус меняется в браузере. Счётчики обновляются.

6.5. Удалить задачу — Delete, метод DELETE
Действие в кнопке: data-action="delete".
window.confirm() сначала запрашивает подтверждение удаления.
Для исходной задачи API выполняется DELETE /todos/{id}.
Локальная задача удаляется из state.localTodos через метод .delete().
ID удалённой исходной задачи заносится в state.deletedIds,
чтобы она не появилась снова после обновления API.

6.6. Открыть профиль — Open Profile
Действие в кнопке: data-action="profile".
openProfile(userId) открывает окно, renderProfile() заполняет его.
В нём показаны сведения и выполненные/невыполненные задачи исполнителя.
Используются уже загруженные пользователи; отдельного GET при клике нет.

6.7. Назначить исполнителя — Assign User
В форме выбирается человек, а в задачу записывается его userId.
Кнопка «Назначить задачу» в профиле заранее выбирает этого исполнителя.
Сама задача создаётся только после отправки заполненной формы.

6.8. Поиск — Search
Событие input читает введённый текст из строки поиска.
getVisibleTodos() сравнивает его с названием задачи через .includes().
Регистр букв не учитывается: перед сравнением текст приводится к нижнему регистру.
Поиск выполняется в загруженных задачах, без отдельного запроса к API.

6.9. Фильтры — Filter
all — все задачи; active — невыполненные; completed — выполненные.
Фильтр исполнителя сравнивает выбранный ID с userId задачи.
getVisibleTodos() применяет поиск, статус и исполнителя одновременно.
Для изменения фильтров отдельный запрос к API не нужен.

6.10. Сортировка — Sort, метод GET
От А до Я: GET /todos?limit=0&sortBy=todo&order=asc.
От Я до А: GET /todos?limit=0&sortBy=todo&order=desc.
sortBy=todo — сортировать по названию задачи.
asc — по возрастанию, desc — по убыванию.
loadTodos() запрашивает порядок у API; локальные задачи и правки
также учитываются при построении итогового отсортированного списка.

6.11. Сбросить — Reset
resetFilters() очищает поиск, возвращает всех исполнителей,
все статусы и сортировку по умолчанию. Сами задачи не удаляются.
Если сортировка была изменена, повторно запрашивает GET /todos?limit=0.

6.12. Обновить список — Refresh, метод GET
refreshData() повторно загружает задачи и пользователей из API.
Сохранённые новые задачи, правки и отметки об удалении остаются.

6.13. Сохранить — Save
persistState() записывает данные через localStorage.setItem().
Сохранение выполняется после успешного изменения задачи.
restorePersistedState() восстанавливает данные при следующем открытии.
Это запись в браузер, а не отдельный запрос POST к серверу.

6.14. Повторить — Retry
При ошибке загрузки кнопка снова вызывает loadTodos() или loadUsers().
«Повторить сохранение» снова вызывает persistState().

6.15. Отменить или закрыть — Cancel / Close
Закрывает модальное окно методом .close() без отправки формы.
Изменения, которые ещё не были сохранены, не применяются.

КРАТКАЯ ШПАРГАЛКА:
Получить = GET; добавить = POST; изменить = PATCH; удалить = DELETE.
В этом проекте используется PATCH для частичного изменения задачи.
PUT здесь не используется.

7. ПОЧЕМУ СОХРАНЕНИЕ СДЕЛАНО В БРАУЗЕРЕ
DummyJSON имитирует добавление, изменение и удаление, но не сохраняет их
на сервере навсегда. Поэтому сайт записывает изменения в localStorage.
Они восстанавливаются в том же браузере и по тому же адресу сайта.
Если запись недоступна, появляется предупреждение и кнопка повтора.
